# Delayed AI billing reconciliation — review only

A successful generation can leave a reservation held when Gateway billing lookup is delayed or unavailable. The existing code stores its receipt but has no later reconciliation path. This change lets the verified founder reconcile up to two existing receipts from Controls. It never generates a response, creates a reservation, enables a flag, renews an expired quote or releases an unknown charge as zero.

One additive migration provides a service-only read RPC over the existing private ledger. It returns only reservation IDs, provider billing IDs, timestamps and original cost evidence; no prompts or family data. Anonymous/authenticated users cannot call it. The server verifies founder membership first, accepts an empty POST or a validated reservation cursor and returns counts and an opaque reservation cursor with no-store. Caller-supplied receipts/costs are rejected.

Each billing result must match the stored generation, model/provider, non-BYOK source and plausible billing time. The original quote is validated at reservation time so an expired quote can settle its historical charge without authorizing a new request. Existing atomic settlement handles replay/conflict, Singapore week attribution and overrun halts. Unknown/failed lookups keep holds. Bounded cursor pagination reaches newer receipts even if the oldest two stay unresolved; completed anchors remain valid, and the end of a pass resets the next check to the start. Unknown cursors fail closed. Overruns are recorded and explicitly reported. The UI aborts late account responses; reconciliation is manual, with no recurring worker or sending.

At most two8second billing lookups plus two5second settlements and a5second inventory read fit the existing45second route limit. Do not expand the batch without reworking deadlines. No raw provider errors or provider receipt IDs reach the browser.
